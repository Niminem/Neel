Each section has buttons and a log. "ok" means the result matched what the harness expected; "FAIL" or "UNEXPECTED" means it did not. The terminal shows the window hooks and, in debug builds, dropped fire-and-forget failures.

Manual checks

  1. Refresh this page (Cmd/Ctrl+R). The window id above must stay the same, the status must return to "connected", and every button must still work. The terminal prints no second "opened" hook for this window.
  2. Close this browser window (not the Quit button) while it is the only window. The terminal prints "[hook] window 1 closed" after 3 s and then "stresstest exited: erLastWindowClosed", and the process ends.
  3. Reconnect and give up: the shim reconnects only after an abnormal close (any code but 1000/1001), which Neel never sends on purpose, so kill the process instead: kill -9 <pid> (the pid is in the asJson() output). Press "whoAmI()" right away: the call is queued while the shim retries (5 attempts, 250 ms to 4 s apart, 7.75 s in total) and is then rejected with NeelDisconnectedError: neel: gave up reconnecting after 5 attempts; every later press rejects at once with neel: connection is closed. A page refresh after a restart of the app works again (a new token is rendered into /neel.js), while the old page cannot reconnect because its token is stale.
  4. No browser: run the binary on a machine without Chrome or Chromium, or pass browsers = @[Default] in startApp. The page opens in a tab of the default browser instead of an app window; everything else behaves the same.
  5. Quit button below: the terminal prints "stresstest exited: erQuit" at once and the window(s) close.
