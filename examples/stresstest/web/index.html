Neel stress test

window ? (main), connection: connecting, calls in flight: 0

Each section has buttons and a log. "ok" means the result matched what the harness expected; "FAIL" or "UNEXPECTED" means it did not. The terminal shows the window hooks and, in debug builds, dropped fire-and-forget failures.

Manual checks

  1. Refresh this page (Cmd/Ctrl+R). The window id above must stay the same, the status must return to "connected", and every button must still work. The terminal prints no second "opened" hook for this window.
  2. Close this browser window (not the Quit button) while it is the only window. The terminal prints "[hook] window 1 closed" after 3 s and then "stresstest exited: erLastWindowClosed", and the process ends.
  3. Reconnect and give up: the shim reconnects only after an abnormal close (any code but 1000/1001), which Neel never sends on purpose, so kill the process instead: kill -9 <pid> (the pid is in the asJson() output). The status above switches to "reconnecting (close code 1006 ...)" at once. Press "whoAmI()" right away: the call is queued while the shim retries (5 attempts, 250 ms to 4 s apart, 7.75 s in total) and is then rejected with NeelDisconnectedError: neel: gave up reconnecting after 5 attempts; every later press rejects at once with neel: connection is closed; the status then reads "closed (close code 1006 ...)".
  4. Refresh after a restart: this needs a fixed port, so start the app as ./stresstest 8765 (any free port). Note the pid from asJson(), kill -9 <pid>, wait for the shim to give up (status "closed"), then start ./stresstest 8765 again. The new run opens a second browser window at the same URL. Now refresh this (old) window: it loads a fresh /neel.js with the new token, binds as window 1 and works again (press "whoAmI()"), while the window the restart opened is displaced and goes dead ("server closed the connection (close code 1000)": both pages carry ?window=1, and the most recent connection wins). Before refreshing, the old page cannot reconnect on its own because its token is stale.
  5. No browser: run the binary on a machine without Chrome or Chromium, or pass browsers = @[Default] in startApp. The page opens in a tab of the default browser instead of an app window; everything else behaves the same.
  6. Quit button below: the terminal prints "stresstest exited: erQuit" at once and the window(s) close.
